## Outcome and authority boundary

The shared architecture and the proving Treasury use case are separated.
Baseline policy/specifications govern registered case profiles; domain
sources, rules, mappings, Gold definitions and generated products are not
shared architecture defaults.

The initial deterministic compiler accepts explicit supported JSON contracts
inside Markdown, not arbitrary business prose. It generates draft metadata,
review context and fixed safe adapters. It does not certify source meaning,
deploy semantic models, activate metadata or create native acceptance evidence.

## Deterministic guardrails

Tests cover omitted/incompatible baseline inheritance, case attempts to
redefine baseline IDs, forbidden override/executable/credential fields,
unresolved authoring placeholders, invalid source/Gold references and
unsupported handlers/layouts/algorithms.

Compilation receipts pin governing baseline documents, current case inputs,
reviewed profile code, compiler implementation and generated outputs.
Normal compiled-case build/deploy rejects stale or edited products before
cloud access. A no-op compile preserves already-built products; a changed
contract invalidates its own generated deployment products, not another case.

Packaged notebook roles reject a pinned manifest for another case before
dispatch/data writes. Enabled object Lakehouses must match the selected
profile's declared layer resources; resource changes require rebinding.
These checks do not turn the control database's global active selection
into simultaneous per-case activation.

These are supported structural/contract checks and isolation evidence,
not a claim that arbitrary prose is correct or baseline files are immune
to human repository edits. Baseline changes still require explicit review,
versioning and downstream impact analysis.

## Additive SQL connector support

Baseline 1.1.0 provides separate reusable Fabric SQL Database and SQL Server
Copy templates. Pinned `connector_type` selects the adapter; both retain
the `sql` transport family, typed projection, identical Bronze sink and
standard Silver/DQ engine. Fabric SQL retains OAuth2 and workspace/artifact
geometry. SQL Server uses a managed Basic SQL connection and no Fabric
source database item, with validated supported connectivity/gateway references.

Compiler, binding, publication preflight, Python descriptors and SQL paging/
readiness guards agree on this distinction. SQL Server native Copy evidence
is mandatory independently of an object's optional capability list.
Compilation/binding never fabricates that evidence. Updated control SQL and
the Copy helper must be deployed together; other SQL Server authentication
modes and native SQL/Copy/gateway acceptance remain outside local proof.

## Preserved compatibility and remaining limits

Historical plans/checkpoints, requirement wording and scoped acceptance
remain records of their original work. `relocations.json` maps former
document locations to their new ownership. Domain-specific implementation
references, diagrams and fixtures reside with Treasury.

Shared module/package names are domain-neutral. Source business dictionaries,
namespace exceptions and the legacy fiscal rule are case-owned; shared
engines dispatch through reviewed adapters. Physical timestamp format aliases
remain codecs, not source selection.

The follow-up agnostic-artefact pass moved all proving-case fixture code,
CSV/schema/manifests, validation evidence and the historical pipeline into
`use_cases/treasury`. Shared modules use neutral filenames and handler
namespaces; the deployment package is `fabric_medallion_deployer`.
Its generic fixture entry points select explicitly declared case adapters.
The source registry, schema bytes, 44 CSVs and source business hashes remain
unchanged; the case audit records the import/path-only provenance rebaseline.
Old external Python imports must migrate to `fabric_medallion_deployer`;
the repository does not retain a duplicate case-named engine.

The domain-extraction parity tests use immutable Git revision
`4d76d7f5e3278ca4b16ed6e3e78ae14b4349b194`, not the moving `HEAD`.
That historical revision must be available when running them.

Ruff passes on the shared runtime, deployment/compiler and case extensions.
The relocated historical fixture code retains 11 existing style findings;
the same findings were verified against the pinned original revision.
No fixture algorithms were restyled to make the relocation appear clean.

The initial new-case compiler is intentionally bounded to managed SQL,
supported generic DQ, explicit same-key dimensions, declared facts/calendars,
simple aggregates and semantic declarations. Unsupported custom algorithms,
new transports or semantic deployment need a reviewed extension, not a bypass.

No Fabric writes, source reseeding, metadata activation, permission changes,
paid resource creation, native execution or commits were performed in this
restructuring pass. Native SQL/Copy/DAG/MLV/layout, migration, recovery,
consumer behavior and business publication remain separately approved gates.
